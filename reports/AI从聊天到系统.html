整场直播可以用一句话串起来：计算从少数机构的机器，走到每个人桌上的电脑、口袋里的联网设备，再走向能理解意图并协调工具的软件。推荐系统开始替我们分发内容，生成式模型开始按意图组织答案，Agent 则把回答接进工具和执行循环。下一场平台竞争，或许会围绕谁能跨应用协调行动、管理权限并赢得信任展开。

01 / 算力走向大众

从占满房间，到装进口袋

每一轮计算普及，都同时改变三件事：谁能用、怎么用、能连到谁。把这三条线讲清楚，历史就不再是公司和产品名单。

ENIAC 是“Electronic Numerical Integrator and Computer”的缩写。它在 1946 年公开亮相，是早期大型、可编程、通用电子数字计算机的重要里程碑，体量约占一间大房间，主要用于弹道计算。谨慎地说它“重要里程碑”，比称作无条件的“世界第一台电脑”更准确：计算史上的“第一台”取决于是否要求电子式、通用、可编程、存储程序等不同条件。[1]

“全世界只需要五台电脑”是个好故事，但不是可靠的历史引文。

这句话常被归于 IBM 总裁 Thomas J. Watson，有时还配上 1943 年的年份；本次查证没有找到足以确认原话的同期记录。直播可以把它当作“后人常用来讲技术预测会失准的轶闻”，同时揭示出处存疑。这样既留下记忆点，也不会用未经证实的故事给历史作证。[5]

个人电脑、图形界面、互联网和移动设备不是单一公司突然发明的。Apple Macintosh 于 1984 年推出；微软 Windows 1.0 于 1985 年发布。Tim Berners-Lee 在 CERN 提出并实现 World Wide Web；Web 是建立在互联网之上的信息系统，不是互联网本身。2007 年 iPhone 把电话、音乐播放器和互联网通信体验整合到一台设备，显著推动触屏智能手机进入大众市场。[2][3][4]

讲移动网络时的稳妥说法

更快的网络降低了传输延迟和成本，为视频、云服务、移动支付等提供条件；但微信支付和支付宝的普及不能归因于单一代际网络。设备、支付基础设施、商业模式和用户习惯也同时成熟。3G、4G、5G 是国际标准框架和能力目标；5G 的具体应用同样需要供需共同演进，不能从标准指标直接预言赢家。[6][26][27]

02 / 软件开始理解人

从“给所有人同一页”，到“按你关心的排序”

推荐算法不是 2016 或 2017 年才出现。Netflix 早在 2006 年就启动了 Netflix Prize 来改进电影推荐；YouTube 团队 2016 年发表了用于大规模视频推荐的深度神经网络研究。你可以把 2016—17 年讲成自己的职业观察：“我开始明显感到算法岗位进入越来越多业务团队，个性化分发也成为普通用户每天都能感受到的产品机制。”[7][8]

这段可以做整场的关键转场：过去的软件更常根据点击和行为，替你筛选、排序已有内容；生成式 AI 则能从自然语言目标出发，组织知识、生成答案和方案。它让搜索、归纳和表达的一部分工作收进了对话界面。但模型说得顺，不等于说得对；答案仍要核验。

不要把 GPT‑4 的能力跃迁归因于“全 GitHub 训练”

微软确实于 2018 年收购 GitHub；OpenAI 早期 Codex 研究也公开提到使用 GitHub 上的公开代码训练代码模型。但 GPT‑4 技术报告没有披露具体训练集构成，不能据此声称 GPT‑4 训练了整个 GitHub，更不能断言这是它“突然开窍”的原因。[9][10][11]

“顿悟”“开窍”可以作为用户体验的比喻：模型跨过一个具体任务门槛时，人会觉得能力突然变了。学术上的“涌现能力”有明确讨论，但研究者也指出，某些突变观感会受评测指标影响。因此更稳妥的解释是：数据、训练与对齐方法、推理策略、工具链和产品工程共同进步；任务达到可用阈值时，体验就像突然开窍。[12][13]

03 / 从回答到行动

变化不只是“会聊天”，而是闭环开始运转

把提示词、上下文、Agent、harness 讲成四种“人机分工变化”，不要硬说成严格按年份发生、全行业一致的四个时代。

01 / 指令

Prompt

把任务讲清楚：要做什么、用什么格式、受哪些限制。

02 / 信息

Context

准备历史对话、项目文件、检索材料和工具返回。

03 / 行动

Agent

模型决定下一步、调用工具、观察结果并继续推进。

04 / 运行

Harness

提供工具、上下文、权限、状态和验证机制。

上下文工程（context engineering）关注的是为任务准备、组织和更新有效信息；上下文学习（in-context learning）是研究术语，指模型根据输入里的说明或例子临时完成任务，两者不是一回事。MCP的全称是 Model Context Protocol（模型上下文协议），它帮助 AI 应用连接工具和数据源；它不是“上下文协议”的泛称，也不会自动替应用解决授权与安全。[14][15][16]

语音稿里的“Hannes / Holis / 哈里斯”按上下文大概率是 harness，可讲作“智能体运行框架”或“运行环境”。“H1”没有足够线索确认，先删掉，除非回听音频后能确定。

为什么编码 Agent 较早显出实用价值？

代码可以在开发环境里运行，可以跑测试，结果也能被检查；这让“读任务—修改—执行—观察—修正”的闭环比较容易搭起来。Anthropic 于 2025 年 2 月发布 Claude 3.7 Sonnet 时，同时将 Claude Code 作为研究预览推出。注意说法是“Claude Code 随 Claude 3.7 Sonnet 发布”，而不是“Claude Code 3.7”。能调工具不等于能无监督交付生产系统；还需要权限边界、测试记录和人工验收。[17]

可乐鸡翅例子仍然很好用：先问做法，再补充饮食偏好和家中食材，最后让 Agent 帮你列购物单或准备订单。关键转折不是提示词越来越华丽，而是 AI 能否使用信息、采取行动，并在付款等高影响步骤停下来请求确认。

04 / 未来判断

AI OS：争夺意图入口和执行控制权

如果 AI 要替人跨应用完成工作，核心竞争就不只是“谁的模型回答更聪明”，还包括谁能安全、稳定地访问用户授权的数据、应用动作和设备能力。

意图入口人描述目标，而不是逐个寻找功能
行动协调跨应用、工具与 Agent 编排任务
权限与身份用户授权、确认、撤销、审计
现有操作系统与硬件管理进程、文件、设备与应用运行

这三项能力可以作为直播里“AI 操作系统”的工作定义：自然语言意图入口、跨应用行动协调、身份与权限治理。传统操作系统还负责进程、内存、文件、设备资源和应用运行，因此能调工具的 Agent 并不因此自动成为 OS。当前“AI OS”更像一个宽泛的方向标签，尚无统一定义；它可能在现有操作系统之上形成 Agent 层，也可能被 Apple、Google、Microsoft 等既有平台吸收，或由云端和企业平台承担。[18][19]

手机 Agent 确实需要系统接口，但未必需要一套全新操作系统。Apple 的 App Intents 让开发者把结构化动作暴露给 Siri、Shortcuts 等系统能力；Android Accessibility Service 可在授权范围操作界面，但 Google Play 对将其用作自主计划和行动通道设有政策限制。平台要在自动化能力、用户隐私、应用方责任和交易安全之间做取舍。欧盟对 Android AI 互操作性的讨论也显示：第三方 Agent 如何获得系统能力，已经成为平台政策议题。[20][21][22]

让预测变成可检验的问题

未来两三年观察：Agent 能不能稳定跨 App 完成高价值任务？用户愿不愿意授予并随时撤销权限？开发者会不会提供标准动作接口？错误能否被发现、回滚和追责？现有 OS 会吸收这层能力，还是第三方/云端 Agent 能成为独立入口？这些问题比“AI OS 必然取代手机系统”更能指导判断。

05 / 平台的护城河

英伟达的价值不止一张 GPU

英伟达适合作为“软硬件生态如何互相增强”的例子，但 CUDA 不是管理整台个人电脑的通用操作系统。CUDA 提供 GPU 编程接口和工具；cuDNN、cuBLAS、NCCL、TensorRT、Nsight、NGC 等软件覆盖常见算子、线性代数、多 GPU 通信、推理优化、性能分析，以及可部署的容器和模型。框架与开发者使用这些积木，可以少造轮子、跑出更成熟的性能。[23][24][25]

所以“谁掌握操作系统，谁就一定成为首富”并不成立为历史定律。系统和应用商店可以影响分发、接口和生态分成，因而有很强的平台议价机会；但结果还取决于硬件销量、网络效应、商业模式、开发者供给、竞争和监管。更有力也更准确的一句话是：平台入口有机会持续捕获价值，但谁赢、能捕获多少，仍要看生态愿不愿意接入、用户是否信任、规则如何开放。
