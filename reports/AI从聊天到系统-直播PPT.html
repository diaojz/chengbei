开场

AI 的下一站，可能不是更聪明的聊天框

而是一个能代表你跨应用办事的入口。今天不押某个产品，沿着技术怎样改变人机分工，推演下一层平台会长什么样。
计算普及 → 软件理解用户 → AI 理解意图 → Agent 执行 → AI OS 假说
讲者提示：先抛问题：如果 AI 不只是回答，而是替你把事办完，它需要什么？
从业者视角｜一条主线，一组可检验的问题

01 / 计算普及

每一代计算，都在回答同一个问题

谁能用得起？谁能用得懂？它能连接到哪里？
大机房 → 个人电脑 → Web → 智能手机
讲者提示：ENIAC 很适合做“巨大计算机”的视觉引子，但五台电脑不要说成确凿史实。
“全世界只需要五台电脑”是常归于 IBM 总裁 Watson 的轶闻，缺少可靠同期出处；可以当作低估普及的故事，不能当作确定原话。 [1][2]
02 / 18
01 / 计算普及

不是某家公司发明了一个时代

1946 · ENIAC：大型通用电子计算的里程碑｜1984 · Macintosh：图形界面走入大众市场｜1985 · Windows 1.0：图形操作环境｜1989–91 · Web：互联网之上的信息系统｜2007 · iPhone：重新组织手机交互
技术突破 + 可用产品 + 产业生态 = 普及
讲者提示：这部分讲“普及”而不是“发明权”。硬件、软件、网络和生态一起把门槛压低。
Web ≠ 互联网；Macintosh ≠ 第一台图形电脑；iPhone ≠ 第一部智能手机。它们是重要的普及节点。 [1][3][4][5][6]

01 / 计算普及

基础设施的价值，常在后来才显现

网络升级降低延迟与传输成本，给视频、云服务、移动支付等体验创造条件。
新能力 × 终端 × 商业模式 × 用户习惯
讲者提示：用3G/4G/5G做转场：我们常常先问“快这么多干什么”，后来才看到新产品组合。
不要说“4G 发明了微信支付”。单一技术通常不能解释产品成功；5G 会带来什么，也要看组合条件。 [7]

02 / 软件理解用户

同一个 App，不再是同一个世界

推荐系统依据用户行为与上下文，对内容排序和分发。你刷到的首页，逐渐变成“为你组织的信息流”。
软件从“同一套菜单” → “不同人的不同首页”
讲者提示：讲自己的体感时标明是个人经历，不把它说成算法诞生年份。
推荐算法远早于 2016 年；Netflix Prize 于 2006 年已围绕推荐展开。2016–17 可以讲成“我在工作中明显感到算法岗位扩张”。 [8][9]
05 / 18
02 / 软件理解用户

算法改变的是“给谁看什么”

平台用行为信号估计兴趣，再把内容排到不同位置。价值来自匹配，风险也来自信息茧房、偏差与注意力竞争。
输入：点击 / 停留 / 反馈　　输出：排序 / 推荐
讲者提示：对比上一页：从“猜你想看什么”走向“听懂你现在想做什么”。
推荐系统是软件理解偏好的早期形态；生成式 AI 则把软件带向“理解表达出来的意图”。

03 / AI 理解意图

搜索给你材料，模型尝试给你组织答案

传统搜索：提出关键词 → 浏览页面 → 比较来源 → 自己综合。
聊天模型：自然语言提问 → 生成整合后的回答。
交互入口从“找信息”转向“表达意图”
讲者提示：可以用“可乐鸡翅”举例：从搜菜谱、比步骤，到一句话问出做法。
模型回答流畅，不等于内容真实；重要事实仍要回到可核查来源。GPT‑4 报告没有披露完整训练数据集。 [10]
07 / 18
03 / AI 理解意图

像“突然开窍”，不等于知道它为什么开窍

能力跨过某个实用门槛时，用户会感到质变。研究中的“涌现能力”有不同定义；部分突变效果也受评测指标影响。
体验上的转折 ≠ 单一、已证实的训练原因
讲者提示：这里主动纠正口述稿里的 GitHub 因果故事，显得更可信。
“微软收购 GitHub → OpenAI 把全部代码喂给 GPT‑4 → 模型开窍”缺少可靠证据。GPT‑4 训练细节并未公开。 [10][11][12]

04 / 从回答到行动

提示词、上下文、Agent：不是严格的年代分期

提示词：把任务说清楚。
上下文：挑选任务需要的信息、历史、文件和结果。
Agent：让模型调用工具、观察反馈、继续推进。
表达任务 → 提供信息 → 执行闭环
讲者提示：用户常说的“Holis/H1”大概率是 harness；口播稿统一用“Agent 运行环境/控制层”并说明没有唯一标准。
Context engineering（上下文工程）不是 in-context learning（上下文学习）。MCP 是连接 AI 应用与工具、数据源的开放协议。 [13][14][15]
09 / 18
04 / 从回答到行动

Agent 的关键：看结果，再决定下一步

读需求 → 修改代码 → 运行测试 → 检查结果 → 修正或交付
闭环让输出变成可观察的行动
讲者提示：代码是较早显现价值的场景之一：结果可以运行、测试、检查；并不意味着 AI 可独立可靠交付任意生产系统。
Claude Code 是产品；Claude 3.7 Sonnet 是模型。Claude Code 于 2025 年 2 月随该模型作为研究预览推出。 [16]
10 / 18
04 / 从回答到行动

能调用工具，不等于可以无限行动

低风险：读取、草拟、总结。
中风险：改文件、发起流程。
高影响：付款、删除、部署、对外发送。
授权范围 + 人工确认 + 可验证结果
讲者提示：把鸡翅例子走完：列清单可以自动；下单付款需要授权确认。
MCP 解决连接协议问题；授权、权限、审计和正确性仍要由具体应用与运行环境设计。 [15][17]
11 / 18
04 / 从回答到行动

人机分工在变，岗位边界也会跟着变

过去：前端、后端、测试、运维、数据等分工。
现在：Agent 能覆盖更多环节，个人需要更强的定义问题、集成和验收能力。
机会是扩大个人产能，不是“所有岗位已经消失”
讲者提示：把演讲者的真实体验放进来：我用 Agent 做项目迭代，但交付责任仍由人承担。
“一人公司”“FDE”等是正在出现的工作形态与趋势，不是所有行业都已完成的组织替代。

05 / AI OS 假说

如果 AI 替人跨应用办事，谁来做总入口？

用户说目标 → 系统识别意图 → 找到应用动作 → 请求授权 → 执行并验证
AI OS = 意图入口 + 行动协调 + 权限治理
讲者提示：这里明确提出你的预测：竞争焦点可能从模型回答质量，扩展到跨应用行动入口。
这是一个分析框架，不是行业统一定义，也不代表现有 Agent 已成为传统操作系统。传统 OS 还负责进程、内存、文件和设备等资源管理。 [18]
13 / 18
05 / AI OS 假说

平台价值来自生态，不只是“占住系统”

操作系统可控制资源、接口和分发；应用商店、开发者工具和用户习惯会放大平台影响。
入口可能有价值，但不是“掌握 OS 就必成首富”
讲者提示：用“有机会捕获价值”替换“必然垄断收入”，你的判断更稳。
价值捕获还取决于硬件、网络效应、商业模式、竞争与监管。CUDA 是强大的 GPU 软件生态，不是通用操作系统。 [19][20]
14 / 18
05 / AI OS 假说

AI 入口未必来自一套全新手机系统

路线 A：现有 iOS / Android 增强系统级 Agent。
路线 B：应用开放结构化动作接口。
路线 C：第三方 Agent 在授权范围内跨应用协调。
新系统 / 旧系统升级 / 开放接口，都会竞争
讲者提示：回扣豆包手机等现象时，仅讲“争夺系统级权限/入口”，具体型号能力需直播前核对官方资料。
Apple App Intents 等能力说明现有系统也在提供动作入口。谁赢仍取决于体验、权限、应用参与度和监管。 [21][22]

06 / 如何检验预测

别猜十年后的赢家，先观察四个信号

跨应用任务完成率是否持续提升？
高影响操作的授权与审计是否清楚？
开发者是否愿意开放可调用动作？
用户是否愿意把持续记忆与权限交给它？
能否完成 × 是否可信 × 生态是否加入
讲者提示：这页是结论的检验方法，让预测能被未来证据推翻。
如果 Agent 长期只能在封闭小场景完成任务，AI OS 假说就需要收缩；如果跨应用协作成为默认体验，系统入口的价值会上升。

收束

下一代软件，可能从“打开 App”变成“说出目的”

今天：人找功能。
正在发生：人说目标，Agent 调工具。
可能的下一步：系统代表用户协调多个服务。
谁听懂意图？谁拿到授权？谁愿意接入？
讲者提示：结尾停在三个问题，邀请观众留言：你愿意让 AI 替你跨 App 做哪件事？
AI OS 是值得观察的方向，不是已经注定的结局。
