# 别再当 Yes 工程师：先选你正在用的工具

AI 写代码以后，我一度以为自己会变成“十倍工程师”。后来发现，我先变成了 **Yes 工程师**。

读文件，Yes。跑测试，Yes。装依赖，Yes。真正浪费的不是点击那一秒，而是注意力被不断切碎：任务明明可以自己跑二十分钟，你却不敢离开电脑。

解决方法不是关闭全部权限，而是把权限分成三层：

1. **活动范围**：AI 能在哪里读写、能不能联网；
2. **日常通行证**：哪些高频、可逆操作以后不再询问；
3. **硬红线**：删除、读密钥、强推、提权，自动模式下也必须拦。

但 Codex 和 Claude Code 的实现完全不同。普通用户通常只用其中一个，把两套配置揉在一篇里反而容易抄错。因此我把教程拆成了两个独立入口，每一篇都可以从头到尾单独完成。

## 我用的是 Codex

配置文件是 `~/.codex/config.toml`，核心是审批策略、沙箱范围、可写目录、项目信任和命令前缀规则。

教程包含完整脱敏配置、`default.rules`、验证方法、回滚方式，以及 Codex 被其他 Agent 委派时为什么要使用不同策略。

## 我用的是 Claude Code

配置文件是 `~/.claude/settings.json`，核心是 `defaultMode`、`allow/deny`、项目级设置，以及执行前的可编程 Hook。

教程包含完整脱敏配置、fail-closed 安全守卫、可选的远程审批 Hook、验证方法和配置被第三方工具覆盖后的恢复办法。

**[进入 Claude Code 完整教程 →](#/p/claude-code-permissions-guide)**

## 不管选哪条，都先记住

- 修改前备份原文件；
- 让 AI 做字段级合并，不要覆盖整份配置；
- 白名单只放高频、可逆、边界清楚的操作；
- 配完既要测试“能不能干活”，也要测试“能不能越界”；
- 不要在普通电脑上开启“永不询问 + 完全访问”。

权限系统真正的高级感，不是再也看不到确认框。

而是确认框终于出现时，你知道：**这一次真的值得停下来。**
