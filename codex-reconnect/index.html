是怎么回事，怎么修

先找到断在哪里，再改配置。把下面的提示词复制给 AI，让它检查当前版本、登录状态和错误日志；确认是 WebSocket 问题后，再考虑切换到 HTTP/SSE。

发布于 2026-08-05 · 更新于 2026-10-19

重连提示只是症状

正在重新连接 2/5 · Reconnecting 2/5

这表示客户端正在重试连接或恢复响应流。代理中断、网络超时、服务端异常和认证失败都可能造成请求失败；仅凭这行字，不能认定是 WebSocket，更不能保证“重试五次后一定降级成功”。

这次更新修正了什么旧版把 0.136 当作统一分界，把所有重连解释成 WebSocket 失败，并额外提高重试次数。新版改为先看证据；保留关闭 WebSocket 的条件方案，去掉统一升级门槛和无依据的参数加码。

✦把下面这段复制给 AI

交给能读取本机配置与日志的 Codex 或其他编程助手执行。它需要先诊断，再决定改哪里。

请实际排查并修复本机 Codex 频繁出现“Reconnecting N/5 / 正在重新连接 N/5”的问题。 1. 检查版本、安装来源、实际生效的配置、登录状态和近期错误日志。结合当前版本的官方文档判断原因，不要预设一定是 WebSocket，也不要自动升级或照搬旧教程。不得输出 API Key、Token 或完整凭证文件。 2. 如果日志支持“代理导致 WebSocket 握手或连接失败”，且当前版本支持关闭 WebSocket，先备份实际配置文件，再做最小修改切换到 HTTP/SSE。不要单纯增加重试次数或超时来掩盖问题。 3. 保留现有模型、登录方式、provider、代理和其他配置。ChatGPT 登录继续使用订阅；API Key 或第三方 provider 保留原地址和认证，不得擅自改成其他计费端点。需要更换 provider 或地址时，先说明具体方案和影响。 4. 不重复添加 TOML 键或段落。修改后检查语法、字段是否受当前版本支持，以及配置是否真正生效；可行时用真实请求验证。语法通过不等于修复成功。 5. 不要关闭承载当前会话的 App。告诉我何时需要完全退出并重开，再用容易触发问题的任务复测。区分“已修改”“请求成功”和“重启后验证通过”，不要承诺永久不再重连。 6. 任何命令报错，先提供报错原文（隐藏凭证）并定位原因，再决定下一步。如果出现“Your access token could not be refreshed / refresh token was already used”，说明需要重新登录，不要继续改传输配置。 最后简要报告：原因及证据、修改内容、备份位置、验证结果和待完成步骤。

?官方配置说明能确认什么

截至本次更新，官方配置参考仍列有 model_providers.<id>.supports_websockets，用于声明 provider 是否支持 Responses API 的 WebSocket 传输。但这不代表每个版本、每个 provider 或每次重连都适合用同一套补丁。

stream_max_retries 在当前文档中描述的是 SSE 流中断重试次数，默认值为 5。因此，不能把界面上的 N/5 直接当成 WebSocket 专属计数。提高到 10 可能延长失败等待，不能修复连接被切断的原因。

stream_idle_timeout_ms 是 SSE 空闲超时，当前文档默认 300000 毫秒。只有确认是空闲超时时，才有理由调整它。

登录方式应结合 codex login status 和实际客户端账户状态判断。旧教程中的 preferred_auth_method 未出现在本次核对的配置参考中；当前文档的 forced_login_method 是登录方式限制，也不能代替实际登录状态。

✎手动处理：先检查，再决定

  1. 记录环境。命令行执行 codex --version 和 codex login status；桌面版同时检查自己的版本与账户。命令行版本不能代表桌面版内置运行时。不要因为旧教程写了版本下限就盲目升级。
  2. 找到生效配置与错误。检查用户配置、当前项目配置、所选 profile 和启动参数；默认用户配置通常在 ~/.codex/config.toml。结合日志确认是握手失败、流中断、超时还是认证错误。
  3. 备份实际要改的文件。以下命令仅适用于默认路径： 
    cp ~/.codex/config.toml ~/.codex/config.toml.bak-$(date +%F-%H%M%S)
  4. 仅在证据支持时关闭 WebSocket。已有自定义 provider 时，优先核实能否在原 provider 内修改 supports_websockets = false，保留地址和认证。ChatGPT 登录如需新增 provider，可在确认当前版本兼容后参考下面的示例。
ChatGPT 登录的条件示例，不是一键通用补丁先确认当前版本支持这些字段和订阅认证路径。API Key 或第三方 provider 不要套用此地址。切换 provider 后还需核实历史会话可见性等行为。

根级设置写在任何 [段落] 之前；已有同名键就修改，不重复添加：

model_provider = "chatgpt-http"

文件末尾添加 provider 段；若已存在，则就地更新：

[model_providers.chatgpt-http]
name = "ChatGPT HTTP"
base_url = "https://chatgpt.com/backend-api/codex"
wire_api = "responses"
requires_openai_auth = true
supports_websockets = false

不要把 ChatGPT 订阅方案的地址替换为 https://api.openai.com/v1。官方将 ChatGPT 登录与 API Key 登录区分为订阅访问和按量访问；仅改 URL 不会自动产生有效 API 凭证，也不能保证请求成功。

注意 TOML 的作用域：根级设置误放在某个表后面，可能仍能通过语法校验，却落入错误的表。这不一定报解析错误，但可能让配置不生效。

✓验证要分三步

  1. 语法通过。Python 3.11+ 可执行下面的检查；路径按实际配置调整。它只打印所选 provider 与 WebSocket 开关，不输出整个配置。
  2. 应用接受并加载。检查当前版本是否识别字段、所选 profile 或启动参数是否覆盖设置。不要把“TOML OK”当成应用已加载的证明。
  3. 新会话复测。保存工作，桌面版用 ⌘Q 完全退出后重开，CLI 退出当前会话再启动；重复之前容易断开的任务，结合日志看传输错误是否消失。一次成功只能证明本次请求成功。
python3 - <<'PY'
import pathlib, tomllib
p = pathlib.Path.home() / ".codex/config.toml"
d = tomllib.loads(p.read_text())
provider = d.get("model_provider")
print("TOML OK")
print("model_provider =", provider)
print("supports_websockets =",
      d.get("model_providers", {}).get(provider, {}).get("supports_websockets"))
PY

线索下一步
WebSocket Upgrade / 握手失败核对代理与 provider 的传输支持；确认字段受当前版本支持后，再尝试 HTTP/SSE。
SSE 也中断或请求超时继续检查代理、网络链路、服务状态与超时证据；关闭 WebSocket 不能解决所有连接中断。
access token could not be refreshed / refresh token was already used属于认证刷新问题。按当前客户端登录流程重新登录；CLI 可执行 codex login。不要继续用传输参数修登录。
401 / 403 / 429 / 5xx结合响应正文、请求地址与服务状态判断认证、访问限制、限流或服务故障；状态码本身不足以确定原因。
解析错误 / 未知字段 / 修改无效检查重复键、表作用域、版本支持与配置覆盖关系。必要时恢复修改前备份并重启。

需要回滚时

先确认本次备份文件名，再把它复制回实际配置路径并重启。不要只删新增段落：若本来有其他 model_provider，应恢复原值。回滚会覆盖备份之后对同一文件的修改，操作前先检查差异。
