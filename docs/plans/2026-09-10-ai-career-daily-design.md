# AI 求职每日一课设计

## 产品目标

把现有一次性技术题库升级为可持续日更的 AI 求职课程。核心受众是已有前端或后端经验、准备转向 AI 应用工程师或 Agent 工程师的人；零基础读者通过术语解释和预备知识也能跟上。衡量标准不是文章数量，而是读者每周能完成一个可运行成果、每月能解释一类系统、12 周能形成一个可展示和可面试的完整项目。

## 课程架构

第一季为 12 周、三个阶段。第 1 月“会调用”覆盖模型 API、Prompt、结构化输出、Function Calling、流式交互与可靠性；第 2 月“会构建”覆盖 Embedding、RAG、检索与重排、Agent、MCP、状态与记忆；第 3 月“会上生产”覆盖评测、安全、可观测、异步任务、成本、部署与系统设计。每周围绕一个交付目标组织七天：原理、设计、后端、前端、可靠性、项目、复盘。每天一节主课，三道题只用于递进自测，不再承担三个互不相关的主题。

## 页面与内容模型

`/tech-notes/` 变为课程首页：今日主课、12 周路线、当前周七日计划、往期归档、岗位能力映射和旧知识库入口。每日详情页固定包含学习目标、心智模型、最小示例、生产陷阱、面试表达、动手任务、自测和权威来源。课程元数据放在独立 JSON 中，由首页脚本渲染，后续日更只需新增课程记录和详情页。页面使用暖纸张、墨色、朱砂橙与工程蓝，强调编辑式排版和可读性；移动端优先，减少折叠内容。

## 生产与分发

日报提示词从“Top 3 面试经验”改为“每日一课”：先读取课程路线和近七天记录，再研究官方文档、论文、真实 JD 与工程案例，生成完整 Markdown/HTML。飞书卡片呈现今日学习成果、三个核心要点、一道自测和全文入口，而不是只列三条标题。抓取失败时不得伪造来源；课程日期、阶段、周次和前后依赖必须校验。

## 验证与发布

静态数据增加结构校验；HTML 做链接、日期、可访问性和移动端检查；脚本做语法测试；本地 HTTP 预览做桌面与窄屏视觉验收。个人站和日报站分别模块化提交，避免跨仓库混合提交。发布后检查 GitHub Actions、线上 URL、页面核心内容和飞书生成结果；无法验证的外部步骤明确标为未验证。
